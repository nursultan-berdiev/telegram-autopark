# 00 — Обзор

## Зачем

Есть Telegram-бот `telegram-autopark` (аренда авто: водители по приглашению, индивидуальные
графики платежей, приём чеков с ИИ-распознаванием, напоминания, отчёты). Есть парк авто с
GPS-трекерами SinoTrack **ST-901M (протокол H02)**. На пилоте подтверждено: живая телеметрия и
**дистанционная блокировка двигателя** через Traccar.

Нужно превратить бота в **платформу управления автопарком**:
1. Расширяемый слой трекеров (старт — SinoTrack через Traccar).
2. HTTP-API как основной интерфейс; бот — один из клиентов (дальше будет веб-UI).
3. Пер-машинные метрики (телеметрия) пишутся в нашу БД.
4. Отдельный сервис-адаптер к Traccar, хостится отдельно.
5. Движок правил: по условиям (просрочка оплаты / ≥ N штрафов / просрочка ТО по пробегу)
   поднимается алерт, и админ может заблокировать двигатель.

## Что строим (три сервиса + Traccar)

```
                 ┌──────────────┐        ┌───────────────────────────┐
   Telegram ───► │ bot (aiogram)│──HTTP─►│                           │
                 └──────────────┘        │         core-api          │──► PostgreSQL
   (будущий UI) ───────HTTP─────────────►│  FastAPI: домен + правила  │   (домен + телеметрия)
                                         │  единственный писатель БД  │
                 ┌────────────────────┐  │                           │
   Traccar ◄WS/REST│ tracker-adapter  │◄─│  HTTP: команды на блокировку│
  (наш AWS-сервер) │ FastAPI:         │─►│  HTTP: /telemetry/batch    │
                   │ провайдеры трекеров│ └───────────────────────────┘
                   └────────────────────┘
```

- **core-api** — владелец доменной БД и всей бизнес-логики. REST для всех клиентов. Движок
  правил и алерты. **Единственный сервис, который пишет в БД.**
- **tracker-adapter** — расширяемый слой к трекинг-платформам. Провайдер = один тип трекера;
  первый — `TraccarProvider`. Тянет телеметрию (Traccar WebSocket), шлёт команды (Traccar REST),
  нормализует и **пушит телеметрию в core-api**. Свою БД не держит. Хостится отдельно (рядом с
  Traccar).
- **bot** — тонкий клиент core-api. Никакого прямого доступа к БД. Только Telegram-специфика
  (диалоги, файлы, рендер алертов, кнопки).
- **Traccar** — уже развёрнут (наш сервер `13.61.199.204`); его compose-файлы — на самом
  сервере в `~/traccar/` (локально нет). Для прода — полный инстанс с MySQL (состав сверять на
  сервере). Адаптер общается с ним; наружу торчит только адаптер.

## Почему так

- **Разделение интерфейса и домена** (req 2): вся логика в core-api за HTTP → бот и будущий UI —
  равноправные клиенты.
- **Адаптер отдельно** (req 4): изоляция протокола трекеров; Traccar/сеть до него не касаются
  домена; можно хостить рядом с Traccar и масштабировать/менять независимо.
- **Расширяемость** (req 1): новый тип трекера = новый провайдер в адаптере; core-api не
  меняется — он всегда говорит с адаптером единообразно.
- **Телеметрия в нашей БД** (req 3): не зависим от ретеншена Traccar; свои метрики, история,
  правила.
- **Блокировка — доменное действие core-api** (req 5) с аудитом и защитным гейтом; клиенты
  (бот/UI) лишь инициируют по кнопке.

## Границы v1

- Штрафы и интервалы ТО — **ручной ввод админом**. Внешние гос-интеграции штрафов — позже.
- Блокировка — **только вручную по алерту**; автономной блокировки нет.
- Прод-Traccar — отдельный инстанс (MySQL), не пилотный H2.
- Юридические аспекты immobilization арендных машин — вне кода (регламент/договор заказчика).

## Глоссарий

- **Трекер (tracker)** — физическое GPS-устройство в машине (ST-901M). Идентифицируется
  `external_id` (в Traccar — `uniqueId`, напр. `9175358042`).
- **Провайдер (provider)** — реализация доступа к трекинг-платформе в адаптере (Traccar, …).
- **Телеметрия (telemetry)** — временной ряд метрик машины (позиция, скорость, зажигание,
  пробег, статус-маска, io).
- **car_state** — последний снимок состояния машины (быстрый «сейчас»).
- **Правило (rule)** — условие (просрочка/штрафы/ТО), при выполнении рождает алерт.
- **Алерт (alert)** — зафиксированное срабатывание правила; клиент показывает и предлагает
  действие (блокировку).
- **Команда (command)** — исходящее действие на трекер (engine_stop/resume, arm/disarm) с
  аудитом.
- **Защитный гейт (safety gate)** — проверка перед блокировкой: `speed==0 && ignition==off &&
  online`. Едущую машину не блокируем.
