# Платформа управления автопарком

Аренда автомобилей: водители по приглашению, индивидуальные графики платежей, приём чеков
с ИИ-распознаванием, GPS-телеметрия, правила и дистанционная блокировка двигателя,
автоматическая проверка штрафов по расписанию.

План рефакторинга и все проектные решения — в [plan/](plan/) (11 брифов).

## Архитектура

```
   Telegram ──► bot (aiogram) ─────────┐
                                       │
   Браузер админа ──► веб-админка ─────┤        ┌─────────────────────────────┐
   (вход по ссылке из бота)            ├──HTTP─►│           core-api          │──► PostgreSQL
                                       │        │  FastAPI: домен и правила   │
   Traccar ◄─WS/REST─► tracker-adapter ┘        │  единственный писатель БД   │
                       (провайдеры трекеров)    └──────────────┬──────────────┘
                                                               │ ставит задачи
                                                        ┌──────▼──────┐
                                                        │    redis    │◄── celery-beat
                                                        │   (брокер)  │    (расписания из БД)
                                                        └──────┬──────┘
                                                               │
                                                      ┌────────▼────────┐
                                                      │  celery-worker  │──► tolom.kg (HTTP)
                                                      │  + Playwright   │──► carcheck.gov.kg
                                                      └─────────────────┘
```

| Сервис | Что делает |
|---|---|
| [services/core-api](services/core-api) | Владелец БД и бизнес-логики. REST для всех клиентов, движок правил, алерты, команды с защитным гейтом. |
| [services/tracker-adapter](services/tracker-adapter) | Слой трекинг-платформ. Провайдер `traccar` (SinoTrack ST-901M, протокол H02): ингест телеметрии по WebSocket и команды по REST. |
| [services/bot](services/bot) | Telegram-клиент: диалоги, файлы, рендер, кнопки. В БД не ходит. |
| [libs/contracts](libs/contracts) | Общие Pydantic-DTO HTTP-контрактов. |
| `celery-worker` | Фоновые задачи: проверка штрафов на tolom.kg (обычный HTTP) и запасная на carcheck.gov.kg, которой нужен браузер (Playwright + Chromium в образе `Dockerfile.worker`). |
| `celery-beat` | Планировщик, читающий расписания из таблицы `periodic_tasks` — частота правится из админки без передеплоя. |
| `redis` | Брокер celery. С паролем и в отдельной сети: очередь задач — это исполнение кода. |
| [tools/carcheck-runner](tools/carcheck-runner) | Расширение Chrome — запасной путь проверки штрафов из браузера владельца, если скоринг reCAPTCHA начнёт резать серверный IP. |

## Ключевые решения

- **Блокировка двигателя — только вручную по алерту.** Автономной immobilization нет.
  Перед отправкой команды — защитный гейт: машина стоит (`speed < 1` узла и `motion=false`),
  зажигание выключено, телеметрия свежая. Отказ гейта — штатный статус `blocked_by_safety`.
- **Подтверждение блокировки** приходит битом 27 статус-маски, а не ответом трекера.
  Если за `COMMAND_ACK_WINDOW_SECONDS` подтверждения нет, фоновая джоба переводит команду
  в `unconfirmed` и поднимает алерт админу («возможно, нет реле»).
- **`online` не хранится в БД** — считается от `last_ts` при чтении, иначе офлайн-машина
  осталась бы «на связи» навсегда.
- **Одометр принадлежит трекеру, а не машине.** Смена устройства или сброс счётчика метит
  пробег недостоверным, и правило ТО не считается, пока админ не переустановит базу.
- **Четыре токена с разными областями:** `CORE_API_TOKEN` (бот → домен и команды),
  `INGEST_TOKEN` (адаптер → только `/telemetry/batch`), `ADAPTER_TOKEN` (core-api → адаптер),
  `FINES_IMPORT_TOKEN` (раннер штрафов → только импорт и список номеров).
- **Два источника штрафов, сверка по номеру постановления.** Основной — tolom.kg: обычный
  HTTP, отдаёт сумму, сумму со скидкой и её срок, статью, название нарушения и место.
  Запасной — carcheck.gov.kg: браузер с капчей и только факт нарушения без суммы. Один и
  тот же штраф из обоих источников не задваивается (частичный уникальный индекс по
  `external_ref`). Все выясненные опытом факты — в
  [plan/10](plan/10-fines-scheduling-admin.md).
- **Суммы храним обе.** Полную и со скидкой (обычно 70 % при оплате в срок): после
  истечения скидки любая из цифр по отдельности врёт, а пересчитать её нечем — скидку
  назначает сервис. Срок скидки идёт от вручения постановления; пока не вручено, отсчёт
  не начался и предельной даты не существует — её и не показываем.
- **Оплаченный штраф закрывается сам.** Он просто исчезает из ответа сервиса, другого
  признака оплаты нет. Поэтому закрытие обвешано предохранителями: итог сервиса обязан
  сойтись с разобранным, номер — быть в реестре, прогон — не оборваться отказом, а
  массовое исчезновение отменяется целиком. Разбор деталей — в
  [plan/10](plan/10-fines-scheduling-admin.md).
- **Отказ сервиса ≠ «штрафов нет».** У прогона три исхода (`ok`, `refused`, `failed`), и
  заблокированная капчей проверка никогда не выглядит как успешная и пустая. Номер, которого
  нет в реестре сервиса, — тоже отдельный случай: это опечатка в госномере, а не чистая
  машина.
- **Расписание фоновых задач — в БД, а не в коде.** Частоту правит человек из веб-админки,
  планировщик перечитывает таблицу раз в 30 секунд. Внутренние служебные джобы с зашитой
  периодичностью остаются в APScheduler внутри core-api.
- **Вход в админку — по одноразовой ссылке из бота.** Пароля у админов нет: личность уже
  подтверждена Telegram. Права проверяются на каждом запросе, а не только при входе.

## Запуск (docker)

```bash
cp .env.example .env   # заполнить BOT_TOKEN, ADMIN_IDS, токены, TRACCAR_*
docker compose up -d --build
```

`REDIS_PASSWORD` обязателен — без него compose откажется стартовать, а не поднимет открытый
брокер. `ADMIN_SESSION_SECRET` и `ADMIN_BASE_URL` включают веб-админку; пустой секрет
выключает её целиком (404), и это осознанно: панель с предсказуемой подписью хуже, чем
её отсутствие.

Контекст сборки у всех сервисов — корень репозитория: им нужен общий пакет `libs/contracts`.
ИИ живёт во внешнем `claude-gateway` (сеть `claude_net`), ключей в образах нет.

## Разработка

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv -r services/core-api/requirements.txt
uv pip install --python .venv -r services/bot/requirements.txt
uv pip install --python .venv -r services/tracker-adapter/requirements.txt
uv pip install --python .venv -e libs/contracts
```

Тесты — по сервисам (у каждого свой `pytest.ini`):

```bash
cd services/core-api      && ../../.venv/bin/python -m pytest
cd services/bot           && ../../.venv/bin/python -m pytest
cd services/tracker-adapter && ../../.venv/bin/python -m pytest
```

Миграции (владелец схемы — только core-api):

```bash
cd services/core-api && DATABASE_URL=... ../../.venv/bin/python -m alembic upgrade head
```
