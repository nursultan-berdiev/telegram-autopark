# tg_auto — Telegram-бот управления автопарком

Регистрация водителей по приглашению и учёт платежей с ИИ-распознаванием чеков.
Функциональные требования: [Функциональные_требования.md](Функциональные_требования.md).

## Стек
- Python 3.12+ · aiogram 3 · PostgreSQL · SQLAlchemy (async) · Alembic · Claude API

## Запуск (dev)

1. Создать и активировать виртуальное окружение:
   ```powershell
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   ```
2. Установить зависимости:
   ```powershell
   pip install -r requirements.txt
   ```
3. Скопировать `.env.example` → `.env` и заполнить (`BOT_TOKEN`, `ADMIN_IDS`, `DATABASE_URL`, `ANTHROPIC_API_KEY`).
4. Поднять PostgreSQL и применить миграции:
   ```powershell
   alembic upgrade head
   ```
5. Запустить бота:
   ```powershell
   python -m bot
   ```

## Структура
```
bot/
  __main__.py        точка входа (long-polling)
  config.py          конфиг из env (админы — только здесь)
  db/                модели и подключение к БД
  middlewares/       определение роли пользователя
  handlers/          обработчики команд и кнопок
  keyboards/         клавиатуры
  services/          бизнес-логика (машины, приглашения, платежи, ИИ, отчёты)
  states/            FSM-состояния
  filters.py         фильтры доступа по роли
  callbacks.py       CallbackData для inline-кнопок
alembic/             миграции БД
tests/               pytest-набор (async SQLite в памяти)
```

## Тесты
```powershell
python -m pytest
```
Тесты проверяют бизнес-логику всех этапов на SQLite в памяти (без сети):
автопарк, приглашения/регистрация, графики (расчёт дат), платежи и защиту от
дублей, отчёты и снимок данных для ИИ, парсинг ответа распознавания чека.

## Что требует боевого окружения для финальной приёмки
Модульная логика покрыта тестами; следующее проверяется на сервере заказчика
с реальными доступами:
- запуск бота с реальным `BOT_TOKEN` и long-polling в Telegram;
- миграции против PostgreSQL (`alembic upgrade head`);
- вызовы Claude API (распознавание чека, ответы ассистента) — нужен `ANTHROPIC_API_KEY`.

## Роли
- **admin** — id из `ADMIN_IDS` (переменная окружения, задаётся только при запуске);
- **driver** — зарегистрированный водитель;
- **guest** — без доступа (приглашение выдаёт админ).
