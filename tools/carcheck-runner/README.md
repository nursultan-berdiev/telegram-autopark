# Проверка штрафов парка (расширение Chrome)

Прогоняет госномера парка через форму [carcheck.gov.kg](https://carcheck.gov.kg/ru)
и заводит найденные штрафы в core-api через `POST /fines/import`.

## Почему расширение, а не скрипт на сервере

Ключ reCAPTCHA v3 привязан к домену: валидный токен выпускается только в
контексте страницы `carcheck.gov.kg`. Обычный HTTP-клиент (`requests`, `curl`)
его не получит никак — сервер ответит `CAPTCHA_LOW_SCORE`.

Headless-браузер токен получить может: прогон через Playwright с серверной
машины 06.09.2026 прошёл. Но reCAPTCHA v3 ставит оценку по поведению и
репутации адреса, и та же связка в тот же день несколько раз получала отказ.
Браузер владельца на бытовом канале — единственный вариант, который не зависит
от настроения скоринга.

Расширение **не обходит защиту**: оно подставляет номер в поле и нажимает
кнопку — те же действия, что и человек. Токен выпускает сама страница в браузере
владельца. Если сервис отказывает (в том числе `CAPTCHA_LOW_SCORE`), прогон
останавливается и показывает причину.

## Установка

1. `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное»
   → выбрать папку `tools/carcheck-runner`.
2. Открыть настройки расширения и заполнить адрес core-api, `FINES_IMPORT_TOKEN` и
   Telegram-id админа. При сохранении браузер спросит доступ к адресу core-api.

   Токен здесь узкий: он открывает только `POST /fines/import` и список номеров
   парка. `CORE_API_TOKEN` сюда класть нельзя — он даёт весь домен, включая
   блокировку двигателя, а расширение живёт в браузере и синхронизируется с
   профилем. Адрес принимается только по `https` (исключение — `localhost`,
   трафик до петли не перехватить).
3. Открыть `https://carcheck.gov.kg/ru`, нажать на иконку расширения →
   «Проверить парк».

## Пробный прогон

По умолчанию включён пробный режим: расширение собирает ответы сервиса, но
ничего не пишет в core-api. Сырые ответы видны в настройках расширения.

### Что известно об ответе сервиса

Успешный ответ снят 06.09.2026 по номеру без штрафов:

```json
{"vehicle":    {"success": true, "message": "", "data": {"govPlate": "...", "brand": "...", ...}},
 "violations": {"success": true, "message": "", "data": []}}
```

Список нарушений лежит в `violations.data`, то есть на уровень глубже, чем
подсказывает имя ключа. Сама запись нарушения (снята по номеру с шестью
штрафами) выглядит так:

```json
{"violationType": "AFP", "protocolNumber": "02-08-051-01-7-382542",
 "violationDate": "2026-08-10T20:06:04"}
```

Из этого следуют две вещи, которые надо знать до включения боевого режима:

- **Суммы в ответе нет вообще.** Штраф заводится с пустым `amount` — его
  придётся проставлять руками или брать из другого источника. `AMOUNT_KEYS`
  оставлены на случай, если сервис начнёт отдавать сумму.
- **Время без часового пояса** — это бишкекское местное, и так оно и
  разбирается. Отдать его на откуп поясу браузера нельзя: у владельца за
  границей ночное нарушение уехало бы на соседние сутки, а по датам считается
  окно правила «N штрафов за период».

Разбор ответа вынесен в отдельный модуль именно потому, что его придётся
править: `node --test tools/carcheck-runner/mapping.test.mjs`.

Нарушения без номера постановления не импортируются: без него повторный прогон
завёл бы дубль.

## Ограничения

- Работает, пока открыт браузер владельца; расписания нет — только кнопка.
- Пауза между номерами — 7 с плюс случайная добавка. Меньше 5 с ставить не стоит.
- Селекторы (`input[name='govPlate']`, кнопка «Проверить» / «Текшер» / «Check»)
  зависят от вёрстки сайта. Если она изменится, прогон остановится с понятной
  ошибкой, а не молча.
